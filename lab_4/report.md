## 1. Цель и постановка

Цель — научиться диагностировать причину «невидимости» данных для статического парсера и собрать данные с динамической страницы двумя путями (Playwright и «дешёвая» альтернатива через найденный XHR), сравнив подходы по измеренным метрикам.

Задачи варианта № 2:

* зафиксировать, что `requests` для `/js/` и `/js-delayed/` возвращает HTML без цитат, а браузер — с цитатами (клиентский рендеринг + задержка);
* реализовать браузерный сбор на Playwright с ожиданиями без `sleep`, предохранителями и журналом;
* реализовать «дешёвую» альтернативу через найденный XHR-эндпоинт `/api/quotes`;
* сверить наборы, замерить метрики, реализовать no-code сценарий в n8n/octoparse, оформить правовой раздел.

**Ограничение по объёму:** тренировочная площадка `quotes.toscrape.com` содержит ровно **100 уникальных цитат**, поэтому требование «≥ 200 записей» физически невыполнимо на этом источнике. Согласно п. 3 методички («если на площадке записей меньше, объём набирается несколькими категориями/страницами/тегами с ведением журнала») собраны **все 100 записей** с полным журналом 10 итераций (≥ 5 циклов взаимодействия выполнено).

Таким образом, вариант № 2 подтверждён: страницы динамические, данные отдаются через XHR, `/js-delayed/` добавляет задержку отрисовки — учтено при выборе ожиданий.

## 3. Схема реализации

### 3.1. Браузерный путь — `collect.py` (async Playwright)

* Явное создание `browser → context → page` внутри `async with async_playwright()`, закрытие ресурсов в `finally`/`async with` (утечек процессов нет).
* Контекст: `user_agent` (Chrome 120), `viewport=1280×800`, `locale="en-US"`, `set_default_timeout(15000)`, `set_default_navigation_timeout(30000)`.
* Блокировка ресурсов через `page.route("**/*", block_resources)` для `image/media/font/stylesheet`.
* Ожидания: `page.goto(..., wait_until="domcontentloaded")`, `page.wait_for_selector("div.quote", state="visible")`, `page.expect_navigation(...)`, `page.wait_for_url(...)`, повторный `wait_for_selector` после перехода. `asyncio.sleep(0.5)` используется **только** как пауза вежливости между итерациями (не как способ дождаться данных).
* Массовое извлечение через `page.eval_on_selector_all("div.quote", fn)` одним вызовом (а не поэлементным обходом).
* Предохранители: `max_iterations=30`, `no_growth_streak ≥ 3` (остановка при трёх итерациях без прироста), дедупликация по ключу `(text, author)`.
* Диагностируемость: перехват `PlaywrightTimeoutError` с сохранением `artifacts/fail_start.png|html`, `artifacts/timeout_iter_N.png|html`; финальный `final_page.png|html`; итоговый журнал `collection_log.csv`.

### 3.2. Дешёвая альтернатива — `collect_api.py` (requests + XHR)

* Эндпоинт найден на этапе диагностики: `GET https://quotes.toscrape.com/api/quotes?page=N`.
* `requests.get(url, timeout=10)` + `raise_for_status()`, разбор JSON, `time.sleep(0.5)` между страницами, ограничение `max_pages=25`, остановка по `has_next == false`.
* Нормализация под общую схему `text / author / tags` (теги — `|`-склейка, как и в браузерном наборе).
* Журнал `collection_log_api.csv`: `page, records_on_page, total, duration_sec, timestamp`.

## 4. Локаторы и устойчивость

| Локатор | Что извлекает | Обоснование устойчивости |
|---|---|---|
| `div.quote` (контейнер) | границы одной записи | Семантический класс, повторяющийся на всех страницах; сохраняется при смене текстов и наполнения. Ломается при переименовании класса `quote` или смене тега |
| `span.text` | текст цитаты | Уникальный класс внутри контейнера; устойчив к вставке лишних обёрток между `div.quote` и `span.text` (descendant-селектор). Ломается при переименовании класса |
| `small.author` | автор | Семантически связан с `<small>`-элементом; переименование `author` сломает, добавление обёртки — нет |
| `a.tag` | теги | Класс-маркер всех тегов; стабилен к изменению языка интерфейса. Ломается только при переименовании `tag` |
| `li.next > a` | кнопка пагинации | **Наименее устойчивый**: дочерний комбинатор `>` ломается при вставке обёртки; класс `next` ломается при редизайне; использование текста «Next →» ломается при локализации |

**Что произойдёт при редизайне (для трёх локаторов):**

1. `span.text` → при переименовании CSS-класса извлечение текста цитаты даст пустые строки; при вставке обёртки `<div>` внутрь `div.quote` — продолжит работать (descendant). Рекомендуемая замена: контейнер `div.quote` + внутри `get_by_role("span")` не подходит, поэтому — `locator(".quote").locator("span").first` или добавление `data-testid` на стороне площадки.
2. `small.author` → при смене текста/языка остаётся стабильным (класс), при переименовании класса ломается. Замена: `div.quote >> text=/by .+/` (regexp по видимому тексту) или `get_by_text(..., exact=False)` по префиксу автора.
3. `li.next > a` → самый хрупкий: меняется текст кнопки («Next →» → «Следующая»), вставляется `div`-обёртка — комбинатор `>` перестаёт матчиться. Рекомендуемая замена: `page.get_by_role("link", name=re.compile(r"next|след", re.I))`, а в идеале — `get_by_label` / `data-testid` от площадки; дополнительно можно опираться на изменение URL и проверять по `has_next` из XHR.

**Smoke-check (проверка полноты после сбора):**

```python
def smoke_check(df, threshold=0.05):
    for col in ("text", "author", "tags"):
        empty = df[col].isna() | (df[col].astype(str).str.strip() == "")
        share = empty.mean()
        if share > threshold:
            print(f"[WARN] {col}: {share:.1%} пустых (> {threshold:.0%})")
    dup = df.duplicated(subset=["text", "author"]).sum()
    if dup:
        print(f"[WARN] дубликатов по ключу (text, author): {dup}")
    print("smoke-check завершён")
```

## 6. Метрики и оптимизация

### Таблица сравнения (измеренные значения)

| Метрика | Playwright | Дешёвая альтернатива (API) | No-code (Octoparse) |
|---|---|---|---|
| Время разработки, мин | 120 | 35 | 25 |
| Записей собрано | 100 | 100 | 100 |
| Время одного прогона, с | 18 | 14 | 43 |
| Число сетевых запросов | 10 | 10 | 10 |
| Трафик, МБ (использовать content.legth в запросе) | 0.42 | 0.15 | n/a (Octoparse использовался в cloud) |
| Пиковая память процесса, МБ (psutil) | 285 | 48 | n/a (Octoparse использовался в cloud) |
| Секунд на запись | 0.18 | 0.16 | 0.43 |
| Устойчивость к редизайну (1–5) | 2 | 4 | 2 |
| Воспроизводимость | Git | Git | .otd + скриншоты |

### Эффект оптимизаций

* **Блокировка ресурсов** (`image/media/font/stylesheet`): трафик снизился примерно с 2.1 МБ до 0.42 МБ (≈ 80 %), время прогона — с ≈ 48 с до 32 с (≈ 33 %).
* **Массовое извлечение** через `eval_on_selector_all`: ≈ 0.02 с на страницу против ≈ 0.35 с при поэлементном `locator.nth(i).inner_text()` в цикле — ускорение ≈ 15×.
* **Отказ от `wait_until="load"`** в пользу `domcontentloaded` + `wait_for_selector("div.quote")` — снижение среднего времени перехода на ≈ 0.4 с/страницу.

«Дешёвая» альтернатива быстрее браузерной в ≈ 5.6 раза по времени прогона и в ≈ 7 раз по трафику при идентичном наборе данных.

## 8. No-code реализация (Octoparse)

Для упрощённого сценария в no-code среде использован **Octoparse**. Задача настроена на сбор данных с той же динамической страницы `https://quotes.toscrape.com/js/`.

### Пайплайн (Workflow) в Octoparse

1. **Go to Webpage:** открытие целевого URL (таймаут установлен на 120 с для корректной отрисовки JS-контента).
2. **Pagination (Loop):** организация цикла по страницам.
3. **Loop Item:** автоматическое определение контейнера одной цитаты (`div.quote`).
4. **Extract Data:** извлечение полей. В окне Data Preview подтверждено корректное определение трех полей: `text`, `author`, `tags`. Значения тегов автоматически объединены в строку через разделитель `|`, что соответствует формату Python-скриптов.
5. **Click to...:** клик по кнопке «Next» для перехода на следующую страницу (настроен цикл до исчезновения кнопки).

**Экспорт задачи:** `nocode/Octoparse_Task.json`, скриншот успешного прогона: `nocode/workflow_screenshot.png`.

Вывод:
1. Разовое исследование - Octoparse. Время разработки всего 25 мин, порог входа минимальный.

## 10. Правовая и этическая оценка

* Работа выполнена **только** на тренировочных площадках `quotes.toscrape.com` и `quotes.toscrape.com/api/quotes`, предназначенных для обучения сбору данных. Сбор с коммерческих сайтов, обход капчи и антибот-защиты, автоматизация входа в реальные аккаунты не выполнялись.
* `robots.txt` площадки не запрещает используемые пути; соблюдались паузы вежливости, ограничение `max_pages`, один прогон без параллельных запросов.
* **Персональных данных (152-ФЗ)** набор не содержит: цитаты, имена авторов и теги — публичные данные, не относящиеся к субъектам ПД. Обработка ПД не осуществлялась, согласия не требовались.
* Скрипты и workflow воспроизводимы из Git, не содержат закрытых кредов; доступы (если бы использовались) вынесены в переменные окружения и не попадают в репозиторий.
